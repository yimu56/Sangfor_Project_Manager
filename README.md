# 项目管理 · 深信服实施交付工作台

一个面向**个人实施交付**的本地项目管理工具，用来管住维保、加点、新实施、测试四类项目的全生命周期：
项目进度、风险问题、附件版本、客户网络信息、设备档案，外加验收 / 维保到期 / 长期未更新三类提醒。

BS 架构，Go 单二进制 + 内嵌前端，双击即用，数据全部留在本机。

## 为什么会有这个项目

实施交付的日常痛点是「记录散、容易漏」：项目进展记在微信里、网络信息记在 Excel 里、设备密码记在备忘录里，
到了月底复盘才发现某个维保早过期、某个项目两周没动、某个验收单找不到了。

这个工具只解决四件事：

1. **项目记录不散乱** —— 一个项目一处，附件、进度、问题、设备、网络全挂在一起。
2. **随手就能记** —— 有进展才记一条，不要求每天打卡；记录可跨阶段多选。
3. **不漏事** —— 维保 60 天到期、验收前 3 天、7 天没更新、14 天没结束，首页一眼看到。
4. **可复用可追溯** —— 客户网络信息按版本走、设备改动用快照、附件改一次留一版，加点 / 转维保直接继承。

## 功能特性

### 项目
- 四类项目：**新实施 / 加点 / 测试 / 维保**，各自独立的阶段模板
- 状态、优先级、产品线（安全产品 / 云产品等）+ 具体产品名称，一个项目可挂多个产品
- 项目编号手填，不做合同金额 / 销售 / 售前等商务字段
- 项目关联：加点关联原项目、测试转实施、验收转维保
- 转化时自动继承：客户、产品、设备快照、网络信息版本、附件（物理复制为新版本）、进度记录（可选）、验收信息

### 客户档案
- 客户 → 多个联系人（姓名必填，电话 / 邮箱 / 角色 / 备注选填）
- **客户网络信息版本管理**：按客户整体出版本，自动生成字段级变更历史（修改前值 / 修改后值 / 操作类型 / 时间）
- **客户设备档案**：型号、序列号、账号密码、拓扑图（多张，图片或文件）、网络信息，改动留痕
- 项目引用网络信息的**指定版本**，不跟随最新版漂移

### 进度与问题
- 进度记录：日期、多阶段、当前进展、存在问题、下一步计划、信息同步（可空）、附件
- 首页取「最新一条进度记录的下一步计划」，为空显示「未定」
- 风险问题：等级 / 负责人 / 状态 / 关闭时间，关闭后仍保留在项目详情中

### 提醒与看板
- 提醒规则：维保到期前 **60 天**、长期未更新 **7 天**、验收前 **3 天**、长时间未结束 **14 天**
- 首页五区：长时间未结束项目、每个项目的下一步计划、本周进度记录、即将到期维保、未关闭问题
- 提醒中心支持标记已读 / 忽略，扫描幂等（同一条件不重复刷屏）

### 附件
- 类型：实施方案 / 拓扑图 / 配置备份 / 授权截图 / 验收单 / 现场照片 / 维保记录 / 其他
- **版本管理**：改一次留一版，旧版本可追溯；单个文件上限 300MB
- 图片与 PDF 在线预览

### 导出
- **Excel**（单工作簿 6 张表）：项目清单、进度记录、客户网络信息、设备清单、问题清单、维保到期清单
- **PDF**（4 类模板）：项目周报、验收报告、客户网络信息表、维保报告
- 验收报告 PDF 直接输出你上传的验收单原件，不额外生成汇总页
- 支持按筛选条件导出、勾选批量导出、批量改状态

### 其他
- 全局搜索：项目 / 客户 / 进度 / 问题 / 附件 / 设备
- 本地自动备份：频率、保留份数、是否含附件均可配
- 深色 / 浅色主题

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | Go 1.26 + `net/http` 标准库路由 | 无 web 框架，路由用 `ServeMux` 的 method + 通配符模式 |
| 存储 | SQLite（`modernc.org/sqlite`） | **纯 Go 实现，`CGO_ENABLED=0`**，Windows / Linux 同一份代码交叉编译 |
| 前端 | 原生 JS + 手写 CSS | 无构建步骤、无 npm 依赖，`embed` 打进二进制 |
| Excel | `github.com/xuri/excelize/v2` | 多 sheet、表头样式、冻结窗格、自动筛选 |
| PDF | `github.com/signintech/gopdf` | 运行时探测系统中文字体，输出 Type0 / Identity-H + 内嵌 FontFile2 |
| 认证 | 标准库 PBKDF2-HMAC-SHA256 | 12 万次迭代，内存会话 Cookie |

代码量：Go ≈ 4.9k 行，前端 ≈ 2.8k 行，共 25 张表，37 个界面。

## 快速开始

### 前置要求

- Go **1.26+**（`go.mod` 声明 `go 1.26.0`）
- 无需 Node、无需 CGO、无需安装数据库

### Windows

```bat
:: 方式一：一键编译（生成 项目管理.exe）
双击 build.bat

:: 方式二：双击已有程序启动
双击 启动.bat    或    项目管理.exe
```

启动后浏览器会自动打开 `http://127.0.0.1:8787`，控制台同时打印本机地址与局域网地址。

> 仓库出于体积考虑不提交 `.exe`（见 `.gitignore`），首次使用请先运行 `build.bat`。

### Linux / macOS

```bash
chmod +x build.sh
./build.sh                    # 生成 sangfor-pm（默认 linux/amd64）
./sangfor-pm                  # 本机使用，自动开浏览器
./sangfor-pm -no-open -host 0.0.0.0   # 服务器部署，不开浏览器
```

交叉编译到其他架构：

```bash
GOOS=linux GOARCH=arm64 OUT=sangfor-pm-arm64 ./build.sh
```

### 命令行参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `-host` | `0.0.0.0` | 监听地址。`0.0.0.0` 允许局域网访问，`127.0.0.1` 仅本机 |
| `-port` | `8787` | 端口被占用时自动向后顺延，最多尝试 20 个 |
| `-no-open` | `false` | 启动后不自动打开浏览器（适合服务器 / 开机自启） |

### 首次使用

1. 打开页面 → 设置管理员**用户名 + 密码**（密码至少 6 位）
2. 先建**客户** → 加联系人 → 录一版网络信息、设备档案
3. 再建**项目**（选客户、类型、产品线），阶段模板自动生成
4. 有进展就去「进度记录」记一条；有问题就在项目里提一条

## 局域网访问

程序默认监听 `0.0.0.0`，同一网段的其他主机可直接用控制台打印的地址访问。

其他主机打不开，通常是防火墙拦了入站：

```bat
:: 双击运行（自动请求管理员权限）
允许局域网访问.bat

:: 或手动执行
netsh advfirewall firewall add rule name="项目管理-PM8787" dir=in action=allow protocol=TCP localport=8787
```

改了端口就把脚本里的 `PORT` 和上面命令的 `localport` 一起改掉。

> ⚠️ 服务是 **HTTP 明文**，且附件与网络信息中的账号密码按需求明文存储。请只在**可信内网**开放，
> 公共网络下建议用 `-host 127.0.0.1` 收回本机。

## 数据与备份

### 数据目录（系统固定，界面不可改）

| 系统 | 路径 |
|---|---|
| Windows | `%APPDATA%\SangforPM` |
| Linux / macOS | `~/.sangfor-pm` |
| 覆盖（测试 / 运维） | 环境变量 `PM_DATA_DIR` |

```
<数据目录>/
├─ data.db          SQLite 主库（WAL 模式）
├─ files/           附件、拓扑图等原始文件
└─ backups/         自动备份 zip
```

**迁移 / 换机**：直接拷贝整个目录即可，数据库与附件都在里面。

### 本地自动备份

- 备份内容：数据库一致性快照（`VACUUM INTO`）+ 附件文件（可选）
- 频率：每 N 小时 / 天 / 周 / 月；保留份数可设，超出自动清理最旧的
- 后台每分钟检查一次是否到达下次备份时间
- 也可在「系统 / 备份」页手动「立即备份」并下载 zip

### 云端 S3

第一版仅保留配置项（Endpoint / Region / Bucket / AK / SK / 前缀），**尚未接入 SDK**，属于后续迭代。
按设计云端只做备份，不做多端同步。

## 数据模型

25 张表，覆盖需求文档中的全部实体：

| 分组 | 表 |
|---|---|
| 账号与环境 | `users` `settings` |
| 客户域 | `customers` `contacts` `net_versions` `net_changes` `devices` `device_changes` |
| 项目域 | `projects` `project_products` `project_stages` `project_relations` `project_devices` `project_device_changes` `project_net_refs` |
| 附件 | `attachments` `attachment_versions` |
| 记录 | `progress` `progress_stages` `progress_attachments` `issues` |
| 提醒 / 维保 | `reminders` `maintenance` |
| 运维 | `backup_config` `export_logs` |

设计要点：

- **版本化**：网络信息按客户整体出版本，字段级差异写 `net_changes`；设备改动写 `*_changes`
- **快照隔离**：项目里的设备是客户设备档案的副本，改项目不动客户档案
- **附件继承**：转化项目时物理复制文件生成新版本，改新项目不影响原项目

## 安全说明

面向个人单用户场景，按需求做了明确的取舍，请知悉：

| 项 | 现状 |
|---|---|
| 账号密码（客户设备） | **明文存储、列表与详情直接展示、导出明文** —— 按需求实现 |
| 传输 | HTTP 明文，无 TLS。仅建议在可信内网使用 |
| 重置密码 | 一次性令牌（30 分钟有效），**仅允许在运行服务的本机生成**，令牌同时写入数据目录 `RESET_TOKEN.txt` |
| 登录防护 | 同 IP 连续 5 次密码错误锁定 60 秒 |
| 会话 | 内存会话，服务重启后需重新登录 |
| SQL | 全部参数绑定；写操作走字段白名单 |

## 已知限制

- 云端 S3 备份未实现（仅配置项）
- 备份只产出 zip，**没有一键恢复**（恢复 = 解压后替换数据目录）
- 单用户，无多账号 / 权限体系
- 附件为物理删除，无回收站；无跨项目去重
- 无日历视图（按需求第一版不做）
- SQLite 单连接串行写入，多端同时操作会排队（个人使用场景足够）

## 常见问题

**双击没反应 / 被杀软拦了**
单文件 exe 容易被误判，加白名单即可。也可命令行运行看报错：`项目管理.exe -no-open`。

**提示端口被占用**
程序会自动顺延端口，控制台看实际地址；也可 `-port 9000` 指定。

**其他主机打不开**
先确认控制台打印的局域网地址与自己的网段一致，再放行防火墙（见上文）。虚拟机 / VPN 网卡的地址通常不可用。

**导出 PDF 报「未找到可用中文字体」（Linux）**
安装任一 CJK 字体（如 `fonts-noto-cjk`），或用环境变量指定：

```bash
PM_PDF_FONT=/usr/share/fonts/truetype/xxx/xxx.ttf ./sangfor-pm
```

Windows 下会自动使用 `simhei.ttf`，无需配置。

**忘记密码**
登录页「忘记密码」→ 在**运行服务的本机**生成令牌 → 输入令牌与新密码。
也可直接看数据目录里的 `RESET_TOKEN.txt`。

**想清空重来**
关掉服务，删除数据目录下的 `data.db*` 与 `files/`，重启后会重新引导初始化。
